# Future Directions

This document outlines potential extensions and research directions for Spherepop, maintaining the distinction between semantic primitives and pragmatic tooling.

## Core Principle

The four primitives `P = {POP, REFUSE, BIND, COLLAPSE}` remain closed. All extensions are either:
- **Infrastructure** (I): Tooling, optimization, integration
- **Research** (Q): Open theoretical questions
- **Experimental** (X): Provisional semantic explorations

No extension becomes normative without explicit theoretical foundation.

---

## Research Directions (Q)

### 1. Plan B Completion (Appendix B Semantics)
**Status**: `spherepop/poset.py` exists but isolated

**Questions**:
- Does repeated minimal-element elimination converge to unique maximal element?
- How do labeled option spaces `O_i = (ℓ_i, C_i)` compose?
- What is the proper quotient operation over the preorder?

**Approach**: Empirical investigation through extended experiments, not assumed invariants.

### 2. COLLAPSE Composition
**Status**: Successive collapse on quotients currently unsupported (THEORY_STATUS.md Q2b)

**Questions**:
- Should `a ~ b` then `a ~ c` yield `[a] = {a, b, c}` by transitivity?
- Or should second collapse be rejected (distinctions already destroyed)?
- What is the composition law for overlapping equivalence relations?

**Approach**: Experiment with transitive closure vs rejection before encoding in core semantics.

### 3. Quotient Predicate Lifting
**Status**: Existential semantics implemented (THEORY_STATUS.md Q3)

**Questions**:
- Should BIND use existential (`∃x ∈ [q]. β(x)`) or universal (`∀x ∈ [q]. β(x)`)?
- Or require predicates be well-defined on equivalence classes?
- How do different lifts affect confluence/regret properties?

**Approach**: Implement alternatives, compare observable behavior in experiments.

### 4. History Compaction
**Status**: Not addressed; histories grow unboundedly

**Questions**:
- What is the correct notion of "observational equivalence" for GC?
- Can we project `h` to `h'` such that all observers agree but `|h'| < |h|`?
- Is there a minimal history preserving all confluent/regretful/admissible properties?

**Approach**: Define compaction as **observer**, not primitive. Test preservation theorems.

## Integration Patterns

### Unix Philosophy

Spherepop operations compose via pipes:

```bash
cat base.json | spherepop refuse '{c}' | spherepop bind 'prefix:a' | spherepop collapse '{a~b}'
```

Each operation:
- Reads Config from stdin (JSON)
- Applies one transition
- Writes new Config to stdout

Chain arbitrary sequences without programming.

### LLM-Assisted Workflow

```
User: "I want to keep only the 'auth' related options and merge similar ones"
LLM:  "I suggest: BIND prefix:auth, then COLLAPSE {auth_user~auth_admin}"
User: [reviews, approves]
System: Commits operations to history h
```

The LLM never writes to `h` directly. It proposes; user commits.

### Observability Stack

```
Spherepop Core → Observers → Metrics → Prometheus/Grafana
                      ↓
                  Validation → Alerts
                      ↓
                  Telemetry → (optional, disabled by default)
```

All observation is read-only. No observer modifies semantics.

## Anti-Patterns (What NOT to Do)

### ❌ Adding a 5th Primitive

```python
# WRONG: Don't add MERGE as a primitive
def merge(cfg: Config, policies: list) -> Config:
    ...
    return Config(..., history=cfg.history + (MergeEvent(...),))
```

Merge is either:
- A **sequence** of existing primitives (REFUSE then COLLAPSE)
- An **observer** that suggests operations
- A **view** over multiple configs

It is never a primitive unless mathematically defined in the paper.

### ❌ Observers with Authority

```python
# WRONG: Don't let observers modify history
def smart_confluent(left, right):
    policy = infer_best_collapse_policy(left, right)
    left_prime = transition(left, policy)  # ← MODIFYING
    right_prime = transition(right, policy)
    return left_prime == right_prime
```

Observers **never** call `transition()`. They compute properties, not continuations.

### ❌ Infrastructure as Semantics

```python
# WRONG: Don't make configuration affect calculus
if config.get("enable_eager_collapse"):
    # Change how COLLAPSE works
```

Configuration affects **performance**, **logging**, **UI** - never semantics.

### ❌ Silently Promoting Defaults

```python
# WRONG: Don't encode open questions as defaults
def successive_collapse(cfg, classes):
    # Assumes transitivity without justification
    merged = transitive_closure(existing_quotients + classes)
    ...
```

Mark as `@experimental`, document in `THEORY_STATUS.md`, study empirically.
