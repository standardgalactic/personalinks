## Common Pitfalls & How to Avoid Them

### Pitfall 1 – Testing Implementation, Not Specification

**Bad**:  
```python
def test_refuse_uses_frozenset_difference():
    """REFUSE implementation uses frozenset.__sub__."""
```

**Good**:  
```python
def test_refuse_removes_specified_options():
    """REFUSE postcondition: option_space' = option_space \ refused."""
```
*Reason*: Tests should reflect the *intended* behavior as specified in `SPE[4D[K
`SPECIFICATIONS.md`, not internal implementation details that could change [K
without affecting semantics.

### Pitfall 2 – Circular Tests

**Bad**:  
```python

    """admissible() returns same as transition() success."""
    for op in operations:
        assert admissible(op, cfg) == can_transition(op, cfg)
```

**Problem**: `can_transition` may be implemented with a try/except that alw[3D[K
always raises the right result—making the test flaky.

**Good**:  
```python

    """admissible() returns False for REFUSE with empty set."""
    cfg = make_config(...)
    assert not admissible(RefuseOp(refused=frozenset()), cfg)
```
*Solution*: Target a specific invariant that cannot be accidentally satisfi[7D[K
satisfied by indirect implementation tricks.

### Pitfall 3 – Flaky Tests

**Causes**:  
- Random generators without fixed seeds.  
- Time‑dependent assertions (e.g., waiting for a network response).  
- Filesystem race conditions or test order dependencies.

**Solutions**:  
- Use `@given` from Hypothesis with a deterministic seed (`hypersuggest`). [K
 
- Mock external resources (`unittest.mock`, `pytest-mock`) so tests run in [K
isolation.  
- Wrap file operations inside temporary directories created by pytest’s `tm[3D[K
`tmp_path`.  
- Run experiments under reproducible conditions (`--random-order` should be[2D[K
be enabled).  

### Pitfall 4 – Overfitting to Implementation

**Bad**:  
```python

    """POP clones items list to avoid mutation."""
```

**Problem**: The implementation detail may change (e.g., move from copy to [K
view) while the specification stays the same. Future changes could break th[2D[K
this test even though functionality is preserved.

**Good**:  
```python

    original = [...]
    popped = pop(original)
    assert original == [...]  # original remains unchanged
```
*Reason*: Focus on observable behavior (`does not mutate the original list`[5D[K
list`) rather than internal cloning mechanisms.

### Pitfall 5 – Ignoring Coverage Thresholds

**Issue**: Failing to enforce `≥ 85%` coverage can hide bugs that manifest [K
only under certain edge conditions (e.g., empty inputs, large data structur[8D[K
structures).  

**Mitigation**: Run the test suite with a coverage checker (`pytest-cov`) a[1D[K
and configure CI pipelines to fail on low coverage.
